# 南栗橋BLP街区 モビリティシェア シミュレーター

住宅（既存街区171戸＋新規街区59区画＝230戸）と、南栗橋駅西口ポート・モビリティステーション（イオン）を、
電動アシスト自転車と電動キックボードの混在フリートで結ぶシェアリングの「ポート配置・台数・運用・費用」を検討するツール。

## 手順
```bash
pip install -r requirements.txt        # Python 3.11〜3.14（テストも行う場合は requirements-dev.txt）
python scripts/precompute_network.py   # map.osm から道路網・距離行列を作成（data/processed/）。座標や住宅を変えたら再実行
streamlit run app.py                   # 画面（事前計算結果を読むだけ）
```
Windows は `start_windows.bat`、Mac/Linux は `start_mac_linux.sh` でも起動できます（`起動方法.txt`）。

### バッチ計算と報告資料
```bash
python scripts/run_study.py --reps 10 --procs 4     # 全72条件×10回（--districts 既存街区 で街区を限定） → data/output/study/results.csv（4コアで約2〜3時間）
python scripts/run_sensitivity.py --procs 4         # 感度分析 → data/output/study/sensitivity.csv
python scripts/make_report.py                       # 報告資料（要 requirements-dev.txt） → data/output/study/報告_モビリティシェア検討.pptx
```
条件：需要シナリオ（低位・高位〈暫定〉／旧シナリオ転換率10%・30%）× 代替乗車（なし(i)／あり(ii)）×
リバランス（a/b/c）× 駅ポート容量（18・25・32台）。各回で「平日・晴れの1日」を40回シミュレーションして
貸出失敗率 20%（充足率80%）・5%・1% を満たす最小の自転車＋キックボード台数を探し、その台数で1か月を回して年間費用を出します。

## ページ構成
| ページ | 内容 |
|---|---|
| 感度分析 | 転換率・ポート数ごとの必要台数とポート位置の感度。配置ファイルの添付・比較 |
| ① ポート最適化 | 需要（シナリオ or 転換率10%刻み）・車種比率・代替乗車・リバランス・駅ポート容量・手続き時間を指定 → 移動時間最小の住宅側ポート位置と、失敗率20%（充足率80%）・5%・1% の最小台数（自転車＋キックボード）。1日 or 1か月の結果、年間費用、a/b/c の比較 |
| ② ポート配置評価 | 地図クリックでポートを追加し、自転車・キックボード台数と収納台数を指定 → 充足率・移動時間・返却失敗・費用。「自動配分」で台数を各ポートと駅に配分 |

サイドバーの主な設定：対象街区（既存・新規。選択は全ページ共通、需要は対象街区の戸数で計算）、駅ポートの容量（初期値25台、変更可）、目標充足率（初期値80%）、期間（1日／1か月）、キックボードの充電停止。

## モデル（`src/engine.py`）
- **需要**：アンケート（2023、23世帯）の時間帯別トリップ ÷ 23 × 戸数 × 転換率 × 目的地比率。住宅⇔駅は片道（朝は駅へ、夕方は駅から）、イオンは往復。
- **車種**：利用者ごとに希望車種を割り当て（自転車60.3%・キックボード39.7%、調査Q16）。往復は同じ車種を希望。
  希望車種が無いとき (i) 利用しない／(ii) もう一方に乗る（代替乗車率を記録）。
- **イベントシミュレーション**：利用希望をポアソン発生させ、車両1台ずつの位置・電池を追跡。
  到着ポートが満車なら「返却失敗」（区画外に置き、次の作業で回収するまで使えない）。
- **キックボード電池**：航続30km、残量20%未満で交換・4時間使えない。電池は日をまたいで引き継ぐ。
- **リバランス**：a 夜（終電後）に初期配置へ戻す／b a＋9:30に駅の余剰（夕方の期待需要＋1台を超える分）を住宅側の不足へ／
  c b＋15:30に住宅側と駅をそろえる。軽トラックはキックボード8台・自転車4台/往復、作業30分＋3分/台＋10分/追加往復。
  `config.yaml` の `rebalance.station_buffer_q` を 0.95 などにすると、駅に残す台数をポアソン分布の分位点にできる。
- **初期配置**：住宅側ポートと駅西口ポートに、不足が起きにくい順に1台ずつ配る（駅ポートの容量以内）。
- **ポート位置**：徒歩（自宅→ポート）＋走行（ポート→目的地ポート、車種比率で加重）＋施設側徒歩（近い入口まで）の合計を最小にする p-median。
- **1か月**：平日・休日（土日祝）を含み、日ごとの気象を月の平年出現日数から抽選。気象で需要と速度に倍率。
- **費用（`src/study.py`）**：車両償却（15万円・3年）、維持1.5万円/年、ポート20万円/か所・5年、用地600円/区画/月、人件費1,500円/時、軽トラック500円/回、平日245日・休日120日で年換算。

前提値と出典は `docs/前提と出典.md`。値はすべて `config.yaml` にあり、画面とバッチ計算の両方に反映されます。

結果は `data/output/study/`（現在は230戸）。既存街区のみ（171戸）の結果は `data/output/study_171/` に保存。

### 街区の追加
`config.yaml` の `paths.houses` に `{name: 街区名, file: data/raw/○○.geojson}` を追加し、
`python scripts/precompute_network.py` を再実行する（GeoPackage / GeoJSON / CSV、点データ）。

## データ（data/raw/）
| ファイル | 内容 |
|---|---|
| `houses.gpkg` | 既存街区の住宅ポイント 171戸 |
| `houses_new_lots_59.geojson` | 新規街区の区画ポイント 59区画（`lot_no`＝区画番号） |
| `new_roads_patch.osm` / `new_roads.geojson` | 新規街区の区画道路（W6m）7本・歩行者専用通路（W2m）25本。計画図をデジタイズ |
| `map_merged.osm` | map.osm＋新規街区の道路（`python scripts/merge_osm.py data/raw/map.osm data/raw/new_roads_patch.osm data/raw/map_merged.osm`）。precompute はこれを使う |
| `map.osm` | OSM抽出（南栗橋駅〜街区〜イオン）。道路網の元 |
| `survey.xlsx` | 2023アンケート集計表（曜日×5〜22時台×交通手段） |
| `ride_logs/` | 走行記録（fit・スマホ位置ログ）と `speed_summary.csv`（自転車12.6・キックボード14.0 km/h） |
